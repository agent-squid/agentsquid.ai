Squid from anywhere you can SSH

Your workstation has the repository, the coding agents, and a test server. You have a phone on the couch or a laptop somewhere else. You want to ask Squid for a change and check the result in a browser.

Tailscale makes this convenient, but you may not have access to it. If you can SSH into your Squid host and that SSH server allows port forwarding, you already have what you need. An SSH tunnel carries your browser connection to Squid.

Keep Squid on loopback

Squid binds to 127.0.0.1 for security: its web server is accessible locally on the host. That keeps the interface controlling your agents, tools, and files off the public network.

SSH local port forwarding lets you reach that loopback address remotely. Your browser connects to a local port on your phone or laptop, and SSH carries the traffic through an encrypted connection to the host. Squid's bind address stays the same.

Your phone or laptop        SSH tunnel        Squid host

Squid tab   :18000  ────────────────────────▶  Squid   :8000
Preview tab :13000  ────────────────────────▶  Web app :3000

                  Addresses on both ends: 127.0.0.1

The host must be reachable over SSH from your current network. A private home-network address alone will not work when you're away; you need a reachable SSH endpoint or an existing SSH route.

One tunnel to Squid

On the host, start Squid:

agentsquid start

Squid runs as a daemon. Note its startup port; these examples use 8000.

On the computer you'll browse from, open a terminal and run:

ssh -N -L 18000:127.0.0.1:8000 your-user@your-host

Replace your-user@your-host with your SSH login. -N opens the connection without a remote shell. -L forwards local port 18000 to port 8000 on the host's loopback address.

Keep that connection open and visit:

http://127.0.0.1:18000/

Use the browser on the same device running the tunnel. The URL uses HTTP locally; SSH encrypts the connection between devices. Your agents continue to run on the Squid host with its files and tools.

A second port for the preview

Squid's tunnel gives you the chat interface. Your project's test server needs its own forwarded port so you can see what the agents are building.

Start the project's development or test server on the Squid host, serving the project you're editing. Suppose it listens on 127.0.0.1:3000. Close the first tunnel with Ctrl+C, then open both forwards in one connection:

ssh -N -L 18000:127.0.0.1:8000 -L 13000:127.0.0.1:3000 your-user@your-host

Now keep two browser tabs open:

Squid:    http://127.0.0.1:18000/
Preview:  http://127.0.0.1:13000/

Ask Squid to change the page, then switch to the preview tab. Live reload works if your development server supports it through the forwarded connection; otherwise refresh after the change. Rebuild or restart when the project requires it.

Use your test server's actual port in place of 3000. Both Squid and the test server can stay bound to loopback. If the app uses a separate backend or live-reload port, forward that too and configure its browser-facing address to use the local forwarded port.

The same setup on your phone

In Termius or another mobile SSH client that supports local port forwarding, connect to your Squid host and add these rules:

Local address      Destination on SSH host
127.0.0.1:18000  →  127.0.0.1:8000   Squid
127.0.0.1:13000  →  127.0.0.1:3000   Preview

Activate the forwards and open the same two URLs in your phone's browser. You can send a coding request in one tab and inspect the running app in the other. The destination address refers to the SSH host; the local address refers to your phone.

Keep the SSH connection active. If the mobile OS suspends the SSH app, reconnect and reload. A tunnel on your laptop does not forward your phone's localhost.

When you're done

Close the SSH tunnel to end browser access. Squid keeps running on the host. If a page fails to load, check that SSH is connected, the service is running, and the destination port matches. If a local port is busy, choose another and update the browser URL.
