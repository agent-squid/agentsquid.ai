Retracted: When to enable worktree isolation

We have withdrawn this article's configuration recommendations. We found a correctness flaw in direct-write mode (worktree.enabled: false): changes can spill into another turn's change list. Those lists cannot reliably attribute edits to an individual turn, and concurrent writers can interfere with each other's edits.

The earlier article recommended direct writes to avoid per-turn promotion conflicts. That advice understated the loss of reliable turn attribution. Separate checkouts per topic can separate features, but turns sharing a topic checkout still share files and do not gain per-turn isolation.

Until this is addressed, avoid concurrent writers in the same checkout and do not treat direct-write change lists as authoritative records of what each turn changed. Use per-turn isolation when you need isolated edits and turn-level attribution, while accounting for its promotion and conflict-recovery limitations.

This retraction does not change runtime defaults or rewrite existing configuration. The default decision is being reconsidered; the original recommendations have been removed from this page.

See the ADR-0025 decision record for the documented issue, and What happens when two agents edit the same line for the isolation mechanics.
